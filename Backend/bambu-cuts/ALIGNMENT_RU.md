# Ручное выравнивание по 3 точкам

Доработка проекта [bambu-cuts](https://github.com/unrelatedlabs/bambu-cuts): вместо
привязки задания по одной точке (левый нижний угол) оператор наводит голову на
**три угла габарита** детали прямо на материале. По трём измерениям строится
2D-преобразование, которое компенсирует сдвиг, поворот листа, ошибку масштаба
и — в режиме `affine` — неперпендикулярность материала.

---

## 1. Почему потребовалось править конвертер

Перед тем как делать выравнивание, я прогнал тестовые SVG через исходный
конвертер. Контур не совпадал с SVG **до всякого выравнивания**:

| Тест | Ожидалось | Было |
|---|---|---|
| прямоугольник 40×20 мм, `viewBox` в мм | 40 × 20 мм | **100 × 50 мм** |
| тот же, `viewBox` в px (типичный Inkscape) | 40 × 20 мм | **377.95 × 188.98 мм** |
| круг Ø40 мм | 40 × 40 мм | **100 × 100 мм** |

Две независимые причины:

1. **`SVGPathJoinerRemoveMRegex.load_svg()`** считал масштаб как
   `scale = vb_width / ширина_рисунка`, то есть **растягивал рисунок, пока он не
   заполнит холст**. Деталь 40 мм в документе 100 мм превращалась в 100 мм.
   Всегда, для любого файла.
2. **Библиотека `svg-to-gcode` полностью игнорирует `viewBox`** (в её исходниках
   так и написано: `# Todo deal with viewBoxes`). Координаты выходили в
   *user units*, а не в миллиметрах — для файлов Inkscape с px-viewBox это
   ошибка в 3.78 раза.

Никакая привязка по точкам это не исправила бы: деталь резалась бы не того
размера. Поэтому:

* убрано растягивание по `viewBox` в `svg_path_joiner.py`;
* добавлен модуль **`bambucuts/svg_units.py`** — корректный расчёт
  `мм / user unit` из атрибутов `width`/`height` и `viewBox`
  (поддержаны `mm`, `cm`, `in`, `pt`, `pc`, `px` при 96 dpi);
* добавлен `GCodeTools._apply_xy_scale()` — единый масштабный коэффициент
  применяется один раз к готовому G-code;
* `GCodeTools._calculate_svg_bounds()` теперь считает габарит по
  **сэмплированным** кривым (раньше брались только концы сегментов, из-за чего
  выпуклости кривых Безье выпадали из bbox и деталь уезжала от нуля).

После правок все тесты дают ровно ожидаемые миллиметры, а bbox G-code начинается
строго в `(0, 0)`.

## 2. Как работает выравнивание

Порядок захвата точек:

```
        P1  ── справа сверху   (max X, max Y)
        │
        P3 ─ P2                P2 — справа снизу  (max X, min Y)
                               P3 — слева снизу   (min X, min Y)  ← начало координат
```

**P3 захватывается последней и остаётся нулём.** Благодаря этому строка
`G92 X0 Y0` в шапке G-code и весь исходный процесс печати работают как раньше —
голова просто должна стоять на P3 в момент старта.

Опорный треугольник берётся из **габарита самого G-code**, а не из SVG. То есть
привязка идёт к тому, что реально порежется, независимо от зеркалирования,
смещений и особенностей конвертации.

### Режимы подгонки

| Режим | Степеней свободы | Что компенсирует |
|---|---|---|
| `affine` (по умолчанию) | 6 | сдвиг, поворот, независимый масштаб X/Y, скос. Проходит **точно** через все 3 точки |
| `similarity` | 4 | сдвиг, поворот, один общий масштаб (МНК, Умеяма) |
| `rigid` | 3 | только сдвиг и поворот, размеры SVG сохраняются 1:1 |

`affine` точнее всех, но полностью доверяет наводке — небрежно поставленная
точка внесёт скос. `rigid` наоборот: гарантирует размер детали, а расхождение
показывает как невязку.

### Защита от ошибок

* определяется зеркалирование при неверном порядке точек;
* отказ при коллинеарных или совпадающих точках;
* отказ, если в G-code есть относительные перемещения XY (`G91`);
* дуги `G2`/`G3`: вектор `I`/`J` поворачивается, при неравномерном масштабе
  выдаётся предупреждение (окружность физически не может остаться окружностью);
* если в строке была только одна координата (`G1 X40`), выписываются обе —
  поворот связывает оси между собой;
* повторное применение к уже выровненному файлу требует подтверждения.

## 3. Запуск

```bash
git clone https://github.com/unrelatedlabs/bambu-cuts.git
cd bambu-cuts

python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python -m bambucuts.webui.app
```

Либо одной командой: `./run.sh`

Открыть **http://localhost:5425**

При первом запуске в консоли спросит IP принтера, серийный номер и access code.
Сохраняется в `~/.bambucuts.conf`. Принтер должен быть в **LAN mode** с
включёнными developer options.

## 4. Порядок работы

1. **Подготовка.** Кинуть SVG (или DXF) в конвертер справа внизу — G-code
   появится в редакторе. Проверить в шапке габарит: он должен совпадать с
   размерами в Inkscape.
2. **Home XY** и выставить **Z = 0** джоггером (или Kiss Z) — как обычно.
3. **P1.** Подвести голову в правый верхний угол габарита детали на материале →
   `Capture` в карточке P1.
4. **P2.** Правый нижний угол → `Capture` в карточке P2.
5. **P3.** Левый нижний угол → `Capture` в карточке P3.
6. Выбрать режим подгонки (обычно `affine`) → **Apply to G-code**.
   G-code в редакторе перезапишется, появится отчёт: поворот, масштабы, скос,
   заданный и измеренный размер, отклонение от прямого угла, максимальная
   невязка. В шапку файла добавляется тот же отчёт комментариями.
7. **Test Frame (no cut)** — голова уезжает на P3, поднимается на Z+5 и обводит
   габарит задания. Ничего не режется. Так видно привязку до того, как нож
   коснётся материала. **После теста Z остаётся на 5 мм — выставить Z = 0 заново.**
8. `Go to` в карточке **P3** → **Print 3MF**.

### Важно

* Позиция головы считается программно, от последнего **Home XY**. Для наводки
  используйте кнопки джоггера, а **не** ручной ввод `G1` в поле «Manual G-code
  Input»: в относительном режиме ручной ввод ломает счётчик позиции (это
  поведение исходного проекта, оно не менялось).
* `Go to` поднимает Z на 2 мм, едет и опускает обратно — нож не тащится по
  материалу.
* Чем дальше друг от друга точки, тем точнее подгонка угла. Ставьте их по углам
  габарита, а не рядом.

## 5. Проверка на синтетике

| Проверка | Результат |
|---|---|
| поворот 2.5°, `affine` | восстановлен как `+2.5000°`, невязка `0.000000 мм` |
| скос 1.98° + масштабы 1.010 / 0.980, `affine` | невязка `4e-16 мм` |
| те же данные, `rigid` | невязка `0.4654 мм` (масштаб не подгоняется — так и должно быть) |
| точки в обратном порядке | зеркалирование обнаружено, выдано предупреждение |
| коллинеарные точки | отказ с внятным сообщением |
| G-code с `G91 X/Y` | отказ с внятным сообщением |

## 6. Что изменено в проекте

**Новые файлы**

* `bambucuts/alignment.py` — вся математика и переписывание G-code
* `bambucuts/svg_units.py` — расчёт `мм / user unit`
* `ALIGNMENT_RU.md` — этот файл

**Изменённые файлы**

| Файл | Что |
|---|---|
| `bambucuts/svg_path_joiner.py` | убрано растягивание рисунка по `viewBox` в `load_svg()` |
| `bambucuts/gcodetools.py` | импорт `svg_units`; новый `_apply_xy_scale()`; применение масштаба в `svg_to_gcode()`; точный габарит в `_calculate_svg_bounds()` |
| `bambucuts/webui/app.py` | `state['alignment']`, хелперы `_alignment_payload()` / `_jog_to()`, эндпоинты `/api/align/*` |
| `bambucuts/webui/templates/index.html` | панель «Manual 3-Point Alignment» под редактором |
| `bambucuts/webui/static/app.js` | логика панели (дописано в конец файла) |
| `bambucuts/webui/static/style.css` | стили панели (дописано в конец файла) |

Остальная логика не тронута.

### API

| Метод | Эндпоинт | Назначение |
|---|---|---|
| `GET` | `/api/align/status` | состояние захваченных точек и позиции головы |
| `POST` | `/api/align/capture` | `{"point": "p1"\|"p2"\|"p3"}` — запомнить текущую позицию |
| `POST` | `/api/align/goto` | `{"point": "..."}` — вернуть голову в точку |
| `POST` | `/api/align/clear` | сбросить точки |
| `POST` | `/api/align/apply` | `{"gcode": "...", "mode": "affine"}` → выровненный G-code + отчёт |
| `POST` | `/api/align/frame` | `{"gcode": "..."}` — обвести габарит на безопасной высоте |
