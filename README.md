# WriteE — приложение для плоттера

Локальное веб-приложение для подготовки рисунка: изображение преобразуется в
SVG, затем в G-code, который можно отправить на FluidNC по Wi-Fi.

## Запуск в Windows

Нужен установленный Python 3.13 и PowerShell. Все команды выполняйте из корня
репозитория — папки, где находятся `README.md` и `requirements.txt`.

### Первый запуск

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe Backend\mvp_app.py
```

Когда сервер запустится, откройте в браузере
<http://127.0.0.1:5000>. Окно PowerShell с сервером оставьте открытым.
Чтобы остановить сервер, нажмите `Ctrl+C`.

### Последующие запуски

Из корня репозитория выполните:

```powershell
.\.venv\Scripts\python.exe Backend\mvp_app.py
```

Повторно создавать окружение и устанавливать зависимости не нужно.

## Проверка

Запустить тесты из корня репозитория:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s Backend\tests -v
```

## Структура

- `Frontend/` — интерфейс приложения.
- `Backend/` — Flask-сервер, генерация изображений, трассировка SVG, конвертер
  SVG в G-code и тесты.
- `Stack/` — архивные материалы, не используемые приложением.
- `requirements.txt` — зависимости активного приложения.

Подробности реализации и ограничения подключения к плоттеру описаны в
[STRUCTURE.md](./STRUCTURE.md).

## Генерация и трассировка

- Изображение по тексту отправляется внешнему сервису только после галочки
  согласия. Вложения запроса остаются в браузере и не отправляются.
- По умолчанию используется бесплатный endpoint Pollinations. Он ограничен
  примерно одним изображением с IP каждые 45 секунд; при лимите сервер получает
  `402`/`429` или занятую очередь `503`. Такие ответы не принимаются как
  изображение: приложение показывает ошибку и время повтора, если сервер его
  вернул.
- Для повторного запроса с тем же текстом используется стабильный seed: он
  позволяет попасть в кэш Pollinations и не расходовать бесплатный лимит.
- У бесплатных изображений Pollinations в правом нижнем углу есть подпись. Перед
  трассировкой backend удаляет её через OpenCV inpaint, чтобы плоттер не рисовал
  логотип как лишние штрихи.
- Можно задать переменные окружения сервера `POLLINATIONS_API_KEY` или `HF_TOKEN`
  (`HUGGINGFACE_HUB_TOKEN`, `HUGGING_FACE_HUB_TOKEN`), чтобы использовать
  endpoint Pollinations с ключом или Hugging Face Inference API. Если ключ не задан или
  провайдер недоступен, приложение возвращает понятную ошибку, а не поддельное
  изображение.
- Растровые файлы трассируются через Potrace с настройками Inkscape Trace Bitmap.
  В интерфейсе доступны режимы `auto`, `brightness` и `edge`: авто выбирает
  режим по яркости и насыщенности, `brightness` подходит для логотипов и тёмных
  линий, `edge` — для фотографий и градиентов.
- Каждый найденный контур записывается отдельным SVG-элементом `<path>` с
  `fill="none"`. Это важно для плоттера: встроенный конвертер считает один
  `<path>` непрерывной линией и иначе соединил бы несвязанные контуры.
- Загруженные SVG-файлы проходят проверку безопасности и не перетрассируются.

Перед отправкой задания на реальный плоттер проверьте его рабочее поле,
настройки осей и калибровку пера.

Для сборки MKS TinyBee в интерфейсе заданы рабочее поле `300 × 350 мм` и
осторожная стартовая подача `5 мм/с`. Режим серво формирует команды FluidNC
`M3 S`; позиции `S700` / `S800` и PWM 50 Гц — только начало калибровки, не
гарантированные углы серво. Отправка такого G-code заблокирована, пока не
подтверждена проверка серво без пера. Сначала настройте PWM-пин в FluidNC и
проверьте направление хода без нагрузки. Значения `S` предполагают стандартную
линейную PWM-карту FluidNC; проверьте вашу настройку `speed_map`.
